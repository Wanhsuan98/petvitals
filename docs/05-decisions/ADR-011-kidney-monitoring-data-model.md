# ADR-011: 血檢改為「一次檢驗多筆項目結果」，並納入尿檢與血壓，支援完整的腎病追蹤

Status: Proposed（第 1 階段已實作）
Introduced: 未定

## Context

v1.0 起，血檢固定記錄 5 個欄位：BUN、肌酸酐、SDMA、血磷、HCT。產品文件只寫「支援 5 項核心指標」，**沒有記錄為什麼選這 5 項**。以實際報告（2026-11-27 使用者提供的 IDEXX ProCyte Dx／Catalyst One 報告，個資已遮蔽）對照，發現幾個問題：

1. **腎貓需要追蹤的項目不只 5 項**。報告上的鉀、鈣、白蛋白、鈉、氯等項目都沒有地方記錄；IRIS 子分期需要的尿蛋白（UPC）與血壓，也完全沒有紀錄的地方。
2. **BUN、肌酸酐、血磷是必填**。只複查其中幾項的回診，使用者只能填舊數字才能存檔，等於產生錯誤資料。
3. **只存數值，不存脈絡**。沒有原始單位、檢驗室參考區間、檢驗時間、儀器，AI 辨識的結果也無法回頭核對；不同儀器或方法的結果混在同一條趨勢線上，看不出差異。
4. **血磷判讀只檢查上限**。IRIS 2026 同時建議血磷不要低於 2.7 mg/dL（[iris.md](../99-reference/iris.md)），但 2.0 也會顯示「血磷控制良好」。另外，「檢驗室參考區間」和「腎病控制目標」沒有分開呈現。

## Decision

### 1. 分四個階段，比賽繳件（2027-01-06）前全部完成，每個階段完成後先驗收再進入下一階段

| 階段 | 內容                                                                                                | 狀態                                                         |
| :--- | :-------------------------------------------------------------------------------------------------- | :----------------------------------------------------------- |
| 1    | 血磷新增偏低等四種狀態；「腎病控制目標」與「檢驗室參考區間」分開說明                                | 已實作，見 [phosphorus.md](../03-domain-logic/phosphorus.md) |
| 2    | 血檢資料結構重構、可儲存部分結果、新增 K／總鈣／iCa／ALB／Na／Cl／TCO₂／HCO₃⁻、AI 辨識擴充          | 待驗收第 1 階段後開始                                        |
| 3    | 尿檢與血壓紀錄、IRIS 子分期顯示                                                                     | 待第 2 階段                                                  |
| 4    | 回診前 AI 摘要（[ADR-010](./ADR-010-ai-blood-test-extraction-and-care-summary.md)）納入以上所有資料 | 待第 3 階段                                                  |

時程很緊（使用者決定，2026-11-27），所以每個階段都要能單獨上線，不讓前一階段的半成品擋住後面。

### 2. 資料結構：`blood_tests` 改為「一次檢驗」，新增 `blood_test_results` 存每個項目

- `blood_tests` 保留，只存這次檢驗的共通資訊：檢驗日期、醫院、備註、核對狀態。
- 新增 `blood_test_results`，**一個項目一列**：

| 欄位                                                      | 說明                                                                  |
| :-------------------------------------------------------- | :-------------------------------------------------------------------- |
| `analyte`                                                 | 項目代碼，見下方項目表                                                |
| `value`                                                   | 標準單位的數值，用於趨勢圖與判讀；無法換成數字時為 null，例如「<0.2」 |
| `raw_value_text`                                          | 報告上的原始寫法，例如 `4.6`、`<0.2`、`4.6 H`                         |
| `raw_unit`                                                | 報告上的原始單位                                                      |
| `reference_range_text`、`reference_low`、`reference_high` | 報告上的檢驗室參考區間，單位同 `raw_unit`                             |
| `measured_at`                                             | 檢驗時間（報告上各儀器的時間不同），可為空                            |
| `instrument`                                              | 儀器或檢驗方法，例如 `IDEXX Catalyst One`，可為空                     |
| `source`                                                  | `MANUAL` 或 `AI_EXTRACTED`                                            |

- **沒有那一列，就代表「未測」**。不用 0 或其他特殊值表示缺項；畫面顯示「未測」，輸入時若 AI 沒辨識到則顯示「未辨識」。
- **一次檢驗至少要有一個項目**，其餘都可以不填。原本 BUN、肌酸酐、血磷必填的限制取消。

**項目與標準單位**（標準單位是趨勢圖與判讀使用的單位）：

| 代碼   | 項目          | 標準單位 | 備註                                                                 |
| :----- | :------------ | :------- | :------------------------------------------------------------------- |
| `BUN`  | 尿素氮        | mg/dL    | 既有                                                                 |
| `CREA` | 肌酸酐        | mg/dL    | 既有                                                                 |
| `SDMA` | SDMA          | µg/dL    | 既有                                                                 |
| `PHOS` | 血磷          | mg/dL    | 既有                                                                 |
| `HCT`  | 血球容積比    | %        | 既有                                                                 |
| `K`    | 鉀            | mmol/L   | 新增                                                                 |
| `TCA`  | 總鈣          | mg/dL    | 新增                                                                 |
| `ICA`  | 游離鈣（iCa） | mmol/L   | 新增                                                                 |
| `ALB`  | 白蛋白        | g/dL     | 新增                                                                 |
| `NA`   | 鈉            | mmol/L   | 新增                                                                 |
| `CL`   | 氯            | mmol/L   | 新增                                                                 |
| `TCO2` | 總二氧化碳    | mmol/L   | 新增。生化儀常見                                                     |
| `HCO3` | 碳酸氫根      | mmol/L   | 新增。血液氣體分析常見；與 TCO₂ 測法不同，分開記錄，不合併成同一條線 |

各項目的數值上下限（防止手誤）在實作時寫進資料契約，並請獸醫師確認。

### 3. 單位：使用者自行換算，原始值一併保存

延續 ADR-010 的做法：程式不自動換算單位。報告單位和標準單位不同時，使用者自己填入標準單位的數值；原始數值和單位照樣保存，供日後核對。沒有填標準單位數值時，`value` 為 null，這筆只保存原始值，不畫進趨勢圖、也不用於判讀。

### 4. 核對狀態：存檔前整份確認

- 表單中有任何 AI 辨識填入的數值時，儲存前必須勾選「我已對照報告核對所有數值」，否則不能送出。
- `blood_tests` 記錄 `verified_at`、`verified_by`。完全手動輸入的檢驗，視為輸入當下已核對。
- 這個做法無法證明使用者真的看過每一格，代價是操作較簡單（使用者決定，2026-11-27）。每筆結果仍保留 `source`，所以哪些數值來自 AI 都查得到。

### 5. 判讀改為「每個項目各自取最新的一筆」

最近一次回診可能沒有驗血磷。血磷提示、分期提示、回診報告改為各自取該項目最新的一筆，並顯示那一筆的檢驗日期，不再假設「最新一次檢驗」包含所有項目。

### 6. 參考區間與控制目標分開呈現；不同儀器的差異留在趨勢圖中

- 檢驗室參考區間跟著每筆結果顯示，標示為「檢驗室參考區間（{儀器或醫院}）」；腎病控制目標維持依 IRIS 與分期計算，標示為「腎病控制目標」。
- 趨勢圖上，儀器或檢驗方法不同的點使用不同的點形狀，提示框顯示儀器與參考區間；換儀器的位置畫一條淡色垂直線，圖下方說明「不同儀器或方法的數值不一定能直接比較」。

### 7. 尿檢與血壓（第 3 階段）

- 新增 `urine_tests`（至少包含 USG、UPC、採樣方式）與 `blood_pressure_readings`（收縮壓、測量方式、測量情境、量測次數）。
- IRIS 子分期的門檻已於 2026-11-27 從 IRIS 2026 分期文件補錄到 [iris.md](../99-reference/iris.md#substaging子分期貓)：貓的 UP/C < 0.2／0.2–0.4／> 0.4；收縮壓 < 140／140–159／160–179／≥ 180 mmHg。程式只使用 iris.md 記錄的數值。
- IRIS 要求子分期依據「多次」量測（UP/C 至少兩次、間隔至少 2 週；血壓多次量測，最好不同天）。因此畫面上只說明「最近一次落在哪個區間」，並顯示目前有幾次量測、間隔多久；量測不足時註明「IRIS 建議依多次量測判斷」，**不把單次數值說成子分期結果**。
- IRIS 對治療中的病患會加註「treating」。尿檢與血壓紀錄要能記錄「目前是否正在使用降血壓／降蛋白尿的藥物」，顯示時加註「治療中」，由使用者依獸醫師告知填寫。
- UP/C 的前提是沒有泌尿道發炎或出血；尿檢紀錄提供備註欄，例如尿沉渣有紅血球時可以註明，畫面上的說明也會提醒這個前提。
- 和分期提示一樣，只顯示「可能需要和獸醫師確認」，不自動判定子分期。

### 8. 既有資料的轉換

1. 新增 `blood_test_results`，RLS 與 `blood_tests` 相同（飼主與 accepted caregiver），並補上 `authenticated`、`service_role` 的 GRANT。
2. 由 migration 把每筆既有血檢的 5 個欄位轉成結果列，`source = MANUAL`。**數值為 0 的欄位不轉**（v1.2 前的預設值，代表沒填），改成「未測」。
3. 讀寫全部改用新表；舊欄位保留一個版本，確認沒問題後，再用另一個 migration 刪除。
4. 套用到正式資料庫前，先在資料副本上演練轉換，並比對轉換前後的筆數與數值。

## Consequences

- **改動範圍大**：13 個檔案、45 處直接讀取血檢欄位，包含表單、紀錄頁、趨勢圖、回診報告、分期提示、血磷判讀與 AI 辨識，都要改成以項目為單位。
- **正式資料庫的資料轉換有風險**：用「新表 + 保留舊欄位」降低風險，出問題時可以退回舊欄位。
- **表單變長**：13 個項目全部列出會讓「30 秒歸檔」變慢。表單依「腎指標、電解質、其他」分組，常用項目在前；搭配 AI 辨識，使用者多半只需要核對。
- **AI 辨識的 JSON schema 會變大**：13 個項目的數值都可為 null，加上原始值、參考區間等文字欄位。結構化輸出限制「可為 null 或聯集型別的參數」最多 16 個，13 個仍在上限內；文字欄位延續「空字串代表沒有」的做法。單元測試會檢查這個上限。
- **時程風險**：四個階段要在約 6 週內完成，測試與核對的時間會被壓縮。每階段驗收後再往下做，必要時第 3 階段可以縮小範圍，例如先只做 UPC 與收縮壓。
- **獸醫師確認**：新增項目的手誤防呆上限、IRIS 子分期的門檻，都需要獸醫師確認後才算定案。

## Alternatives Considered

- **在 `blood_tests` 直接加欄位**（13 個項目 × 原始值、單位、參考區間、時間、儀器）：表會變得非常寬，每新增一個項目就要改表，而且「未測」仍要靠 null 表示，和「辨識不到」分不清楚。捨棄。
- **整份檢驗結果存成一個 JSONB 欄位**：彈性最高，但沒有資料庫層級的型別與範圍檢查，趨勢查詢也較麻煩。這個專案一向用資料庫 CHECK 和 Zod 雙重把關，捨棄。
- **程式自動換算單位**：方便，但每個換算係數都要查證，用錯會讓數值差好幾倍。延續 ADR-010，捨棄。
- **每個欄位各自確認核對**：比較嚴謹，但項目一多操作就很繁瑣。使用者選擇整份確認。
