# ADR-010: 新增 AI 血檢報告辨識與回診前照護摘要，AI 只整理資訊、不做判斷

Status: Proposed
Introduced: 未定（實作完成後補上版本號）

## Context

PetVitals 到 v1.2 為止所有「判斷」都是寫死的規則：血磷依分期比對上限（[phosphorus.md](../03-domain-logic/phosphorus.md)）、分期提示（[ADR-006](./ADR-006-stage-review-hint.md)）、體重警示（[weight-alert.md](../03-domain-logic/weight-alert.md)），沒有任何 AI 功能。

兩個使用上的痛點，用規則做不好：

- **血檢要手動輸入**：飼主拿到的是紙本或照片形式的醫院報告，要自己找出 BUN、肌酸酐、SDMA、血磷、HCT 再逐欄輸入。各醫院的報告版面、項目名稱（例如 `CREA`／`Cre`／肌酸酐）、單位都不一樣，打錯一個小數點就會影響血磷提示與分期提示。
- **回診前不知道該跟獸醫說什麼**：紀錄頁有趨勢圖、回診報告有表格，但飼主要自己從幾個月的資料裡看出「最近哪裡變了」，再轉成要問獸醫的問題。現有報告適合獸醫掃視，不適合飼主事前整理。

另一個觸發點是「2026 法國皇家 AI for Pets 創新徵件計畫」（繳件截止 2027/01/06）。比賽要求作品包含 AI 應用，評分中「AI 應用深度」佔初選 25%、決選 20%。比賽注意事項也有幾條會直接影響設計：

- 涉及健康的功能只能定位為「資訊整理、照護提醒、輔助判斷」，不能讓人以為作品可以診斷，或取代獸醫。
- 提供個別化健康建議的畫面，要在**同一個畫面**清楚顯示主辦單位指定的提示文字，不能只放在頁尾或條款頁。
- 以既有作品延伸參賽，要揭露既有基礎與新增內容，新增部分建議不低於整體 60%（由團隊自行聲明）。

比賽只是觸發點，以下決策都以「對飼主有用、而且不違反醫療定位」為準，參賽與否不影響這份 ADR 是否成立。

## Decision

### 1. 只做兩個功能，AI 的角色都是「整理」

| 功能               | AI 的角色                | 輸入                                           | 輸出                               |
| :----------------- | :----------------------- | :--------------------------------------------- | :--------------------------------- |
| **血檢報告辨識**   | 從報告照片抄出數值       | 一張血檢報告照片                               | 結構化數值，用來預填新增血檢表單   |
| **回診前照護摘要** | 把照護紀錄整理成白話重點 | 去識別化的照護與血檢數據＋規則引擎已算出的結果 | 近期變化摘要＋可以問獸醫的問題清單 |

兩者都**不產生新的臨床判斷**。血磷是否超標、分期提示、體重警示仍然只由現有規則計算；AI 摘要只能引用這些結果，不能推翻或另外下結論。

### 2. 血檢辨識：AI 只預填表單，使用者確認後才存檔

1. 使用者在新增血檢頁上傳或拍攝報告照片，伺服器端呼叫模型，用 structured output 取回 `testDate`、`hospitalName`、`bun`、`creatinine`、`sdma`、`phosphorus`、`hct`，以及每一項的單位與原文標籤。
2. 結果**只用來預填表單**，不會直接寫進資料庫。使用者看過、修改、按下儲存，才會走現有的 `BloodTestSchema` 驗證與寫入流程。辨識出錯的最壞結果是「表單填錯一格、使用者沒發現」，跟手動打錯一樣，不會多出一條繞過驗證的寫入路徑。
3. **單位不自動換算**。現有資料契約規定數值要用 mg/dL、ug/dL、%（[blood-test.md](../02-data-contract/blood-test.md)）。辨識到其他單位（例如 SI 制 umol/L）時，那一欄留白，並標示「報告使用 umol/L，請自行換算後填入」。換算係數一旦用錯，會讓肌酸酐差到約 88 倍，代價太高，不交給模型。
4. 找不到、看不清楚的欄位留白，不讓模型猜。預填的欄位要有視覺標示（例如「AI 辨識，請核對」），讓使用者知道哪些需要對照原始報告。
5. **照片不保存**。照片只在這次請求的記憶體中處理，不寫進 Supabase Storage，也不寫進 log。這樣不用新增儲存空間與對應的 RLS，也符合資料最小化原則。

### 3. 回診前照護摘要：先去識別化，固定輸出格式

1. **送出的資料先去識別化**：只送數值與日期，例如每日體重、輸液量、飲水量、血檢數值、目前 IRIS 分期，以及規則引擎算出的血磷狀態、分期提示與體重警示。**不送**貓名、飼主或協作者資訊、醫院名稱、備註欄自由文字。備註可能含有人名或電話，又無法可靠過濾，所以第一版直接排除。
   **趨勢數字由程式先算好**（例如前後 30 天平均與變化百分比），AI 只把算好的數字寫成文字，不自己從原始資料計算，詳見 [care-summary-input.md](../03-domain-logic/care-summary-input.md)。
2. 資料期間固定為**近 6 個月**，與紀錄頁預設篩選一致（[ADR-009](./ADR-009-records-period-filter-and-charts.md)），也接近一般回診間隔會回顧的期間。
3. 輸出用 structured output 固定成三段：
   - **近期變化**：哪些數值上升、下降或持平，附上期間與數字。
   - **系統提示回顧**：引用規則引擎已觸發的提示，例如「最新血磷高於目前分期上限」，不另外加入新的判斷。
   - **可以問獸醫的問題**：例如「體重這兩個月下降 4%，是否需要調整飲食或輸液？」
4. System prompt 明確禁止：
   - 診斷用語，例如「已進入第 3 期」「腎衰竭惡化」
   - 治療、用藥、輸液劑量或飲食處方建議
   - 推薦特定品牌或產品
   - 預後判斷

   需要調整照護方式的地方，一律寫成「建議和獸醫師討論」。

5. **需要使用者主動按「產生摘要」**，不在頁面載入時自動呼叫，避免無謂的費用，也讓使用者知道這段文字是 AI 產生的。
6. 第一版**不保存摘要**到資料庫，所以不新增資料表或欄位。代價是每次重新產生的內容可能不完全相同，見 Consequences。
7. 摘要顯示在回診報告頁，獨立成一個「AI 整理（僅供參考）」區塊。使用者可以選擇是否把它一起列印。

### 4. 提示文字放在 AI 結果的同一個畫面

- 血檢辨識結果區塊和 AI 摘要區塊**各自**緊接著顯示提示文字，不只靠頁尾或 `/service` 的全文。
- 提示文字使用比賽注意事項「使用者提示與專業諮詢」段落指定的文字（實作時從活動頁逐字複製）。它的意旨與現有的[醫療免責聲明](../99-reference/medical-disclaimer.md)一致，兩份並存不衝突。
- 現有免責聲明的「顯示位置」清單要一併加上這兩處。

### 5. 模型與供應商：Anthropic Claude API

- 使用 Anthropic 的 Claude API（`@anthropic-ai/sdk`）。依公司規範避免中國來源的 AI 服務，這個選項符合。它的影像理解與 structured output 可以同時滿足兩個功能，不需要另外接 OCR 服務。
- 預設模型 `claude-opus-5-5`；`effort` 在血檢辨識用 `low`，在摘要用 `medium`。建立評估資料後，再依準確率與費用決定是否改用較小的模型（例如 `claude-haiku-5-5`）。
- 開啟 server-side fallback（`fallbacks: "default"`）。模型拒答時改由備援模型處理；整條鏈都拒答時，回傳「目前無法產生，請稍後再試」，不讓頁面壞掉。
- API 金鑰只存在伺服器端環境變數 `ANTHROPIC_API_KEY`，**不加 `NEXT_PUBLIC_` 前綴**。只從 Server Action 呼叫（與 backend.md 一致），瀏覽器不會直接接觸 API。照片經由 Server Action 上傳，所以大小要低於 Server Action 的 body 上限，見 [blood-test-extraction.md](../02-data-contract/blood-test-extraction.md)。
- **API 資料的保存與使用**（2026-11-27 查證 Anthropic 官方頁面，實作時同步寫進 [backend.md](../04-architecture/backend.md)）：
  - **保存期間**：一般 API 用戶的輸入（含照片）與輸出，會在收到或產生後 **30 天內自動刪除**。例外包括：使用 Files API 等有自己保存期限的功能、依法需要保存，以及被安全系統標記違反使用政策（最長保存 2 年）。我們以 base64 直接送照片，不使用 Files API。來源：[How long do you store my organization's data?](https://privacy.claude.com/en/articles/7996866-how-long-do-you-store-my-organization-s-data)（頁面標示更新於 2026-07-01）。
  - **不用於訓練**：商業產品（含 Anthropic API）的輸入輸出預設不會用於訓練模型。例外是使用者主動回報回饋，或另外明確同意。PetVitals 不會送出回饋。來源：[Is my data used for model training?](https://privacy.claude.com/en/articles/7996868-is-my-data-used-for-model-training)（頁面標示更新於 2026-08-18）。
  - **Covered Models**：Fable、Mythos 系列至少保存 30 天，並會經過自動安全審查。`claude-opus-5-5` 與 `claude-haiku-5-5` **不在名單內**，適用上述一般規則。之後若換成 Covered Models，要重新評估。來源：[Covered Models](https://support.claude.com/en/articles/15425695-covered-models)。
  - **處理地點在台灣境外**：`inference_geo` 預設為 `global`（可能在任何可用地區處理），另一個選項是 `us`（只在美國處理），沒有台灣或亞洲的選項。來源：[Data residency](https://platform.claude.com/docs/en/manage-claude/data-residency)。依個資法的告知原則，使用 AI 功能的畫面要說明「資料會送到境外的 AI 服務處理，一般情況下 30 天內刪除（違反服務使用政策等特殊情況可能保存更久），不用於訓練」。告知文字不能比官方說明更絕對，例外情況也要寫出來。
  - 以上是 Anthropic 公開頁面的說明，不是合約條款的法律解讀。政策若有更新，以官方最新頁面為準。

### 6. 權限、費用與使用上限

- 飼主與 accepted caregiver 都能使用兩個功能，與血檢讀寫權限一致（[ADR-007](./ADR-007-caregivers-edit-delete-care-data.md)）。伺服器端呼叫前先確認使用者對這隻貓有權限，不能只靠前端隱藏按鈕。
- PetVitals 所有功能永久免費（[ADR-002](./ADR-002-subscription-tier-model.md)），AI 也不例外，但每次呼叫都有實際費用。因此每隻貓每天設上限：**血檢辨識 10 次、摘要 5 次**。腎貓通常 1–3 個月驗一次血，10 次足以應付同一份報告重拍、或一次補登多份舊報告；上限寫進資料契約文件。上限要在伺服器端計數，不能只靠前端。
- 計數用的資料表、RLS 與併發處理見 [ai-usage-log.md](../02-data-contract/ai-usage-log.md)。只保存次數、狀態與 token 數，不保存任何照片或 AI 輸出內容。

## Consequences

- **新增外部依賴與費用**：多一個付費 API、一個伺服器端金鑰、一個需要監控的失敗點。AI 失敗時兩個功能都要能退回原本流程：表單照常手動輸入，報告照常顯示，只是沒有 AI 區塊。
- **辨識錯誤仍可能被使用者漏看**：流程上已要求使用者確認，但使用者可能直接按儲存。現有的數值上下限驗證（例如肌酸酐最多 30）只擋得住離譜值，擋不住「2.1 被辨識成 2.7」這種合理範圍內的錯誤。預填欄位的視覺標示是主要防線。
- **摘要內容不穩定**：同一份資料兩次產生的文字可能不同。因為不保存，也無法事後查「當時 AI 說了什麼」。之後如果要把摘要放進正式報告存檔，再評估是否保存。
- **照片內容會送到外部 API**：雖然不保存，報告照片上可能有飼主姓名、晶片號碼、醫院資訊，這些仍會送到 Anthropic 處理。上傳畫面要提示使用者可以先裁掉這些部分。
- **Prompt 與禁止事項需要維護**：模型更新或 prompt 調整後，要用固定的測試資料重新確認輸出沒有出現診斷或處方用語。實作時要建立這組測試案例。
- **與比賽的關係**：這兩個功能是 PetVitals 首次加入 AI，參賽時要揭露既有基礎（記錄、圖表、推播、協作）與本次新增內容。「新增佔 60% 以上」由團隊自行聲明，這份 ADR 不替這個比例背書。
- **得獎後的合作優先權**：比賽注意事項規定，作品著作權歸參賽團隊。但得獎名單公告翌日起 3 個月內，主辦單位有優先評估與洽談合作的權利。這段期間得獎團隊要和第三方談這個作品的合作前，應先向主辦單位確認合作的可能性。在簽署合作意向書之前，不限制團隊繼續開發、展示或使用作品。PetVitals 是個人專案、所有功能永久免費，這條只會影響「得獎後 3 個月內和其他廠商談合作」的情況。

## Alternatives Considered

- **傳統 OCR（例如 Tesseract）加規則對應欄位**：不用付費 API，但各醫院報告版面、項目別名、單位差異很大，規則會越寫越多；中英混排與手機照片的辨識率也不穩定。捨棄。
- **AI 辨識後直接存檔**：操作最少，但等於多一條繞過人工確認的寫入路徑，錯誤數值會直接影響血磷與分期提示。捨棄。
- **讓 AI 自動換算單位**：方便，但換算係數錯了，後果是數值差好幾十倍，而且使用者難以察覺。捨棄，維持資料契約的「自行換算」。
- **AI 摘要加入飲食或營養建議**：比賽主題有提到營養建議，但飲食調整對腎貓屬於治療的一部分，超出「資訊整理」的定位，也容易碰到比賽禁止的醫療與產品宣稱。改成產生「可以問獸醫的問題」。
- **把完整紀錄（含備註、貓名）送給模型**：摘要可能更貼近實際，但違反資料最小化，備註欄的個資也無法可靠過濾。捨棄。
- **頁面載入時自動產生摘要**：使用者不用多按一次，但每次開報告都產生費用，也不容易讓人意識到內容是 AI 產生的。捨棄。
