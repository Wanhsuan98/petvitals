# ADR-009: 紀錄頁共用時間篩選，並依臨床用途重新拆分趨勢圖

Status: Accepted
Introduced: v1.2.0

## Context

用 2 年份的測試資料（約 1,700 筆打卡、20 筆血檢）實際操作紀錄頁時發現：

- 血檢清單一次列出全部紀錄，要一直往下滑。
- 「體重 vs 輸液量」擠了 700 多個點，每日輸液量在 80–120 間跳動，看不出趨勢。
- 「BUN/Crea vs 血磷」中，肌酸酐（約 2–3）與 BUN（30–60）共用同一個刻度，肌酸酐被壓成一條平線，但它是 IRIS 分期最主要的指標。
- 血檢圖的橫軸是分類軸，不同間隔的檢驗被畫成等距，趨勢斜率失真。
- 新增血檢表單的 BUN、血磷預設為 0，沒填就送出會存成 0，被判斷為「血磷正常」。正式資料已出現 1 筆。

## Decision

1. **圖表與清單共用一個時間篩選**（近 3 個月／6 個月／1 年／全部），狀態記在網址 `?range=`。分開篩選會出現「圖上有、清單找不到」的落差。
2. **預設近 6 個月**。共用篩選只能有一個預設值，各候選的取捨：
   - 3 個月：每日體重圖最清楚，但血檢（腎貓通常 1–3 個月驗一次）只有 1–3 筆，看不出血檢趨勢。
   - 1 年：血檢趨勢完整，但每日資料 365 點，需要週彙總才看得清楚，近期細節被平滑掉。
   - 6 個月：血檢約 2–6 筆、每日資料約 180 點，兩者都還看得清楚，也接近一般回診間隔會回顧的期間。
3. **清單用「顯示更多」（每次 10 筆）而不是頁碼**，適合手機操作。
4. **分期提示、最新血磷、回診報告不受篩選影響**，永遠用全部資料中的最新一筆。
5. **圖表依臨床用途拆分**：腎指標圖（肌酸酐 + IRIS 區間色帶，SDMA 右軸）、血磷圖（目前分期上限虛線）、體重 vs 輸液（7 天平均／週彙總）。**BUN 不畫進圖表**，保留在清單與報告。
6. **橫軸改為時間軸**，新增 `chartjs-adapter-date-fns` 與 `date-fns`（MIT 授權、非中國來源）。
7. 血檢 BUN／肌酸酐／血磷**必須大於 0**，表單不再預設 0，Zod 與資料庫一起改。

## Consequences

- 篩選與彙總在 client 端用已取得的全部資料計算，不改查詢。紀錄頁仍會一次撈全部歷史；資料量造成的載入時間是另一個議題（首次渲染效能），不在這次範圍。
- 血磷上限虛線用「目前」分期，舊的檢驗若在不同分期時做的，虛線不代表當時的目標；系統沒有保存分期變更歷史，圖例會註明。
- 不把 BUN 畫進圖表，習慣看 BUN 趨勢的使用者要改看清單；如果之後有需求，可以在腎指標圖加成可切換的線。
- 加 CHECK 前必須先修正既有的 0 值資料，否則 migration 會失敗。
- 多兩個前端依賴，增加一點 bundle 大小。

## Alternatives Considered

- **圖表與清單各自篩選**：彈性較高，但兩邊期間不一致時容易誤讀，捨棄。
- **頁碼分頁**：手機上按鈕小、打斷閱讀，捨棄。
- **自訂日期區間**：彈性最高，但手機上選兩個日期操作繁瑣，固定四個選項已涵蓋主要情境，之後有需求再加。
