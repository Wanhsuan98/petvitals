# ADR-003: 協作者人數上限訂為 3 人（含 owner），用常數而非分級方案

Status: Accepted

## Context

多照護者協作功能需要決定一隻貓最多能有幾位協作者。選項包括：不設上限、依付費方案分級（例如 2 人方案 / 5 人方案 / 無上限方案）、或訂一個簡單的固定上限。

累積口碑階段的目標是先讓功能好用、讓使用者願意分享給朋友，而不是精算座位數收費。

## Decision

每隻貓最多 3 位協作者，**owner 本人算在這 3 位裡面**（不是 owner + 3 位協作者 = 4 人），實作為一個常數 `MAX_CAREGIVERS_PER_PET = 3`，不做分級方案。

## Rationale

- 真實情境多半是「飼主本人 + 配偶/同居人 + 偶爾支援的家人或臨托保母」，3 人涵蓋絕大多數家庭結構。
- 把 owner 算進總數裡，邏輯更單純：「這隻貓總共有幾個人能碰」比「owner 之外還能加幾個人」更容易讓使用者跟開發者雙方理解與溝通。
- 用常數而非分級方案，避免在還沒有真實使用數據前就過度設計計費邏輯。

## Consequences

- 好處：實作簡單，不需要額外的方案管理邏輯；符合累積口碑階段「先求好用」的優先順序。
- 代價：如果之後真的有多人協作需求超過 3 人的家庭或機構型使用者（例如貓咪保姆公司），目前的設計無法滿足，需要之後再評估是否拆分更高階方案。
