# ADR-007: 協作者可以新增、編輯、刪除照護與血檢紀錄

Status: Accepted
Introduced: v1.2.0

## Context

20260922 的 code review 發現協作者政策原本是 `for all`，任何協作者都能刪光整隻貓的病史，因此改成協作者只能 `select`/`insert`（見 `20260922000000_restrict_caregiver_delete.sql`）。

後來發現兩個問題：

- 血檢與打卡紀錄存好之後，**不論飼主還是協作者都沒有編輯、刪除的入口**，手動輸入打錯（例如血磷小數點）無法修正，錯誤數值會一直影響血磷警示、分期提示與回診 PDF。
- 協作者打錯自己新增的紀錄，只能請飼主處理，與產品「讓照顧責任平均分攤」的初衷不符。

曾討論過「飼主決定協作者權限層級（僅檢視／可編輯）」，最後決定不做：維持單一協作者角色，省去權限欄位、升級攻擊防護與介面複雜度。

## Decision

飼主與已接受邀請的協作者，對 `daily_care_logs`、`blood_tests` 擁有相同的新增、編輯、刪除權限（migration `20261016000000_allow_caregivers_edit_delete_care_data.sql`）。

仍然只有飼主能做的事（政策不變）：修改貓咪資料、邀請與移除協作者、管理提醒排程、刪除貓咪。

編輯的限制：

- 血檢可修改所有數值與日期；每日打卡只能修改內容，**不能改打卡時間（`recordedAt`）、所屬日期（`date`）**，否則會打亂今日達成度與體重趨勢。
- 紀錄不能被搬到另一隻貓（更新時不送 `pet_id`）。
- 刪除要經過「確定刪除」二次確認，因為無法復原。
- 打卡紀錄的編輯、刪除入口目前只在「今日已記錄」清單；較早日期的打卡紀錄沒有清單可操作（血檢則是整份歷史清單都可以）。

## Consequences

- 任何協作者都可以刪除病史。這是為了照顧責任分攤而接受的風險；目前**沒有「誰修改或刪除了什麼」的稽核紀錄**，飼主無法追查。若之後出現糾紛，需要加上稽核軟刪除或修改紀錄，另開 ADR。
- 刪除紀錄後，血磷警示、分期提示、體重趨勢、今日達成度都是即時計算，會自動反映，不需要額外處理。
- 較舊的打卡紀錄打錯仍無法修正，直到之後補上歷史清單。
- 想限制協作者只能看，目前沒有選項；若未來有此需求，需要重新評估分級權限。
