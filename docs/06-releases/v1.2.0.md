# v1.2.0

Status: In Development (spec/design 已完成，尚未動工實作)

## Goals

讓照護不因單一人力而中斷：開放多照護者協作，並把主動提醒排程做進日常使用流程。

## Changes

### Caregivers

- [x] 新增 `pet_caregivers` 資料表與 RLS 政策（owner OR accepted caregiver）
- [x] `find_user_id_by_email` 邀請查詢函式（security definer，僅 service_role 可呼叫）
- [x] `settings/caregivers` 邀請/移除管理頁
- [x] 邀請流程（email 比對，沿用現有登入機制；`/settings` 顯示待接受邀請通知）
- [x] `getCatProfile()` 支援協作者（不只認 owner），連動修正 `settings/page.tsx` 的唯讀顯示
- [x] `owns_cat_profile`/`is_invited_caregiver` security definer 函式，修正 `cat_profiles`/`pet_caregivers` 互相查對方造成的 RLS 無限遞迴
- [x] **產品決策變更**：拿掉訂閱狀態綁定，多照護者協作改為永久免費（見 [ADR-002](../05-decisions/ADR-002-subscription-tier-model.md) 的 Update）
- [x] Code review 修正：caregiver 不再有 `delete` 權限、人數上限改成 DB trigger 兜底（防併發競態）、email 查詢改不分大小寫、`acceptCaregiverInvitation` 檢查是否真的更新到資料列、owner 身分檢查抽成共用的 `getOwnedCatProfile()`

詳見 [../01-requirements/caregivers.md](../01-requirements/caregivers.md)

## Migration

Caregivers 相關（已套用，`supabase/migrations/20260918*.sql`）：

- `20260918000000`：新增 `pet_caregivers` 表與其 RLS
- `20260918010000`：`cat_profiles`/`subscriptions` 補協作者讀取政策、`daily_care_logs`/`blood_tests` 加上協作者存取（含訂閱檢查，後續版本移除）
- `20260918020000`：`find_user_id_by_email` 邀請查詢函式
- `20260918030000`：修正 `cat_profiles`/`pet_caregivers` 的 RLS 無限遞迴
- `20260918040000`：補上 `service_role` 對 `cat_profiles`/`daily_care_logs`/`blood_tests` 的 grant（防禦性補強，目前無程式路徑用到）
- `20260918050000`：拿掉協作者存取的訂閱狀態檢查
- `20260922000000`：caregiver 拿掉 `delete` 權限，只留 `select`/`insert`
- `20260922010000`：`enforce_caregiver_cap` trigger，用 advisory lock 兜底人數上限的併發競態
- `20260922020000`：`find_user_id_by_email` 改用 `lower()` 不分大小寫比對

Notification 相關（尚未實作）：新增 `reminder_schedules`、`push_subscriptions` 表時，需依本專案慣例明確 `grant` 給 `authenticated`/`service_role`（見 [../04-architecture/backend.md](../04-architecture/backend.md) 的維運提醒）。
